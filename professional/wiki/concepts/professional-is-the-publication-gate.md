# Professional is the pre-send disclosure GATE on gists and external communications

**Established 2026-08-08.** A gist — and any external communication — is subject to a **pre-send privacy
and disclosure review, and that review is Professional's, as a GATE, not an optional reviewer.** The
grounding is Jon's own framing, `[TRANSCRIPT:2026-04-20, relayed via SSP]`: *"Help me write the skill
gist for the wiki since that is an external communication? …"* — a gist is external communication by his
own words, so the disclosure review sits in the work-context lane. SSP first told the trunks "nothing
about the gist is yours," then corrected it: the gist's **authorship** may be SSP's, but its
**publication** is Professional's gate. Two different questions.

## What the gate checks (the disclosure axis, not content quality)

1. **Third-party names** — no person other than Jon without that person's explicit consent (family
   first). Verify independently, at the primary, not on the author's word. See
   [[no-names-in-public-artifacts-without-consent]].
   - **Convention adopted 2026-08-08 (from the SSP lane, after the v3 exercise): a public artifact that
     asserts anything about who it names must do so as a POSITIVE LIST, never a negative universal.**
     *"No person other than me is named"* is a claim about everything the author did not write, so any
     later edit that adds a name falsifies it silently. *"Named here: me, and X/Y credited for public
     work — that is the whole list"* is a claim about what was written, checkable against the body in
     seconds, and an edit that adds a name makes the list *visibly* incomplete instead of *invisibly*
     false. The v3 gist had certified the negative universal while its body named Karpathy; a peer
     caught it. **Gate rule: reject a negative-universal name claim; require the positive list.**
2. **Actuarial disclaimer — three-part.** Jon's own dictated disclaimer separates *personal opinion /
   not an actuarial opinion / no bearing on his employer*. All three, or the gate holds. See
   [[jon-professional-disclaimer]]. **A disclaimer carrying only the first two clauses is insufficient
   whenever the piece names him as an actuary in public** — the higher-exposure case.
3. **Exposure from naming machinery** — repo names, paths, dated defects, scripts. Low while the repos
   are local/private (no reachable target); becomes real the day any repo goes public (a Jon gate).
   Prefer describing a defect *by behavior* over naming the script.
4. **Employer identity** — gated, unresolved. The disclaimer's clause 3 is the standing protection.
5. **Work / client / claims data** — never in a public artifact.

## This gate carries the Drive-race exposure too — screen a settled copy, never a fresh Drive write (2026-08-11)

If this gate ever `grep`s or reads a file **freshly written to a Drive path**, it binds only the bytes
that exist when it runs (#15) — and on Drive those bytes can lag the write, so the screen can read
pre-materialization (absent/partial) bytes and **false-PASS**, shipping unscreened content. This is the
same code-level exposure found in CFL's bake `GATE 6` (`content_screen` greps `$OUT` right after the
generator mutates it). A 120-trial repro did **not** reproduce it, but not-reproduced is not absent
(#20). **Standing rule for this gate: screen a settled/committed/local copy of a candidate, never a
fresh Drive write** — settle first, or screen off-Drive. Cheap, and correct regardless of the race's
frequency.
