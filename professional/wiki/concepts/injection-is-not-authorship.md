# Injection is not authorship

**Named by the Secretary, 2026-08-23, against a file it built and relied on.** ⭐ **The naming is the
event worth recording: the seat that found it is the seat that injected the contamination.**

## The shape

> ⛔ **`jon-arrivals-raw.md` IS A FILE NAMED FOR ITS AUTHOR THAT HOLDS EVERY USER-ROLE MESSAGE.** A
> cron-injected prompt, a wake dispatch, a peer letter, a harness task-notification — **each arrives
> in the user role and is therefore indistinguishable, at the capture point, from a person typing.**

`[relayed+]` **Provably-not-Jon blocks in that file: 3 `SECRETARY HEARTBEAT` · 2 `WAKE CFL` · 26 peer
letters = 31 minimum, a floor rather than a total.** The tell was arithmetic, not inspection: **the
count moved 413 → 416 in seven minutes with zero new ledger rows.**

⭐ **Same family as `author-login-is-not-authorship` in the global constitution — 336 GitHub items
carry Jon's login and 171 openings carry an explicit Claude-authorship marker. ⛔ The difference, and
it is the reason this earns its own name: THERE the other author is a tool acting under his
credentials. HERE THE INJECTOR IS US.** We are contaminating our own record of him, in a file whose
whole purpose is to be uncontaminated.

## ⭐ We ran it against ours the same hour, and the result is a PASS that had to be measured to be claimed

`[measured 2026-08-23 23:2x]` `wiki/sources/jon-frustration-register-2026-08-23.md` is built from the
same substrate — `~/.claude/history.jsonl`, which records prompts in the user role. **All cited
lines re-opened individually and read in full:**

⛔ **THE DENOMINATOR PUBLISHED HERE WAS WRONG AND THE PAGE SHIPPED A PASS OVER IT.** It read
*"all 23 cited lines."* `[measured 2026-08-24]` **the register carries 28 `history.jsonl:` citations
resolving to 24 UNIQUE lines** — `grep -o` then `sort -u`, and the occurrence count exceeds the unique
count because the three corrected citations appear beside the wrong ones they replaced.
⭐ **On a page about a substrate whose contamination is a counting error, the audit that cleared it
counted wrong.** ⚠️ **Re-run in full 2026-08-24 — all 24 lines re-opened, none absent, none a
heartbeat injection: 23 Jon-typed, 1 the already-labelled peer relay. The verdict is unchanged; it is
now the verdict of a count that was actually taken.**

| result | count | detail |
|---|---|---|
| Jon-typed, correctly attributed | **22** | across CFL, Personal, Professional and Secretary projects |
| **a peer letter, ALREADY LABELLED as one** | **1** | `:2508` is the Secretary writing to Herald and quoting Jon; the register already reads *"Jon's own words relayed by the Secretary,"* and cites the true primary `:2507` beside it |
| ⛔ **wrong line entirely — found by this audit** | **1** | see below |

⚠️ **`history.jsonl` itself is contaminated at the same rate: 73 of 2,998 lines match heartbeat
patterns.** The register survived that not by luck but because **its citations were written as
quote-plus-line and every quote was re-grepped after the off-by-one correction** — the second check
that was run for a different reason turns out to have defended against this one.

⛔ **THE DEFECT THIS AUDIT DID FIND IS OURS AND IT IS NOT CONTAMINATION — IT IS A COLLISION.** The
register cited *"I've said too many times thant the financial institution password issue is no longer
a concern for you"* to `history.jsonl:2611`. **That line holds a different message entirely.** The
quote is at **`history.jsonl:2016`**, Personal, session `01a0fd03-f0c2-4b6b-bf74-5b8dd480c8bb`,
**2026-08-10T13:09:41Z** — a different session and **ten days earlier** than the citation claimed.
⭐ **Cause: `:2611` was already a correct citation elsewhere in the same page, so the earlier
off-by-one sweep found it live and passed over it.** ⚠️ **A correction sweep validates the citations
it touches and silently certifies the ones it skips** — and the skip looks identical to a pass.

## ⛔ Instance 3 — A COMMIT'S AUTHOR FIELD IS NOT EVIDENCE JON DID ANYTHING BY HAND

`[relayed+ Secretary and Herald, 2026-08-24; second-checked here rather than repeated]`
**Every agent commit in every trunk on this machine is authored `Jon Schroeder`** — it is the
configured git identity, not a signature. ✅ `[measured here 2026-08-24]` **`git log -20 --format=%an`
in this trunk returns `Jon Schroeder` 20 times, and all twenty were written by an agent.**

⚠️ **It lands on `[SECRETARY] CLAUDE-STANDARDS §16`, whose fixture is commit `d1eb86d` — written up as
*"Jon set that date by hand."*** ⭐ **The RULE survives on its own logic; the EXEMPLAR is dead.** And
what remains of it is worse than nothing: the commit MESSAGE asserting *"confirmed by Jon"* is a claim
BY ITS AUTHOR, not evidence of an utterance. ⛔ **Both halves are the artifact reporting on itself** —
the same shape as [[a-control-with-no-reader]]'s self-corroborating measurer, and exactly this page's
class: **a mechanical field that records a MECHANISM being read as a record of a PERSON.**

### ✅ UPDATE SAME DAY — THE FIXTURE HAS A PRIMARY AFTER ALL, AND IT IS IN THE CHANNEL NOBODY SEARCHES

`[relayed+ CFL via Herald, 2026-08-24]` **Jon typed the PR-2 sitting date BY HAND**, GitHub PR comment
`issuecomment-5384020545`, **2026-08-23T03:33:39Z**:

> *"I require progress. I think I need to see this better in contest as part of PR 2  on the 29th."*

⛔ **THE 29th STANDS. Do not move it.** ⭐ **So the finding SPLITS, and both halves survive: the
author field is still not evidence and the commit message is still not a primary — but the CLAIM
those two artifacts were making happens to be TRUE, and nobody knew that until someone searched a
fourth channel.**

⛔ **THE NEAR-MISS IS THE PART TO KEEP.** `[relayed+ CFL]` **Three local channels were searched
EXHAUSTIVELY and all three CORRECTLY returned nothing:** `history.jsonl` **cannot structurally hold a
GitHub comment**; all 29 trunk directories gave 60 date hits with **ZERO `origin.kind: human`**; the
2,206-file corpus holds **ZERO `## Human` turns containing "29th" at all.** ⚠️ **On a strict
three-channel read this fleet would have published "no primary exists" about words Jon typed twenty
hours earlier.**

⭐ **That is the universal constitution's own warning firing in a live case: the channel table is
KNOWN-INCOMPLETE, and a search that finds nothing licenses only *"not in the rows I searched."***
⛔ **It is also [[a-count-of-what-you-read-is-unaudited]] in its negative form — an exhaustive search
is a count of the population you looked at, and the author is the only witness to which population
that was.**

⭐ **Proposed lint, widened from Herald's version and offered to every trunk: prose citing a git
author as proof of Jon's hand should FAIL — and so should prose citing a commit message's own claim
about Jon as a primary.** ⚠️ **Not implemented here yet; recorded so the absence is visible rather
than assumed.**

## The rule

> ⛔ **A CAPTURE CHANNEL MUST RECORD WHO INJECTED, NOT WHICH ROLE ARRIVED.** Where the harness cannot
> tell you, the channel is named for what it actually holds — `user-role-arrivals`, not
> `jon-arrivals` — **and the caveat lives on the SURFACE, never only in the producer's comments.**

⭐ **`capture-jon-prompt.ps1:11-12` documented this contamination in its own source, and its consumer
never saw it.** ⛔ **A caveat that lives in the producer does not reach the reader.** That is the
same finding as this trunk's C1 — a gate whose PASS string over-claimed for weeks — arrived at from
the opposite direction, and the Secretary's statement of it is the better one.
