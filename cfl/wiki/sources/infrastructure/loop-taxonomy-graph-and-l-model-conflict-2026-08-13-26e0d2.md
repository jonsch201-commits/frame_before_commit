# An HTML thinking/memory graph request surfaces a live naming collision between two taxonomies

## Summary

Jon asks for an HTML graph of the branching/memory framework behind frame-before-commit,
ground-before-stating, and memory-branching. Building it, Claude finds that "loop taxonomy" names
two distinct objects in the wiki: the ratified seven workflow loops (`concepts/loop-taxonomy.md`,
which states "Conflicts: None") and a separate, undocumented, L-numbered model GBS places itself
inside ("L2, the grounding loop — ear->voice gate"). The delivered graph is built to resist
flattering the architecture — every node carries a status colour and its live falsifier where one
exists — and nothing is written to the wiki; the conflict and the graph are both handed back for
Jon's disposition.

## Key Claims

- **Two different objects in the wiki are both called "loop taxonomy," and one page's own
  "Conflicts: None" is wrong.** The ratified seven (Session, Checkpoint, Ingestion, Skill
  Improvement, Ratchet Rules, Hypothesis, Selection) are workflow loops; ground-before-stating
  places itself as "L2, the grounding loop — ear->voice gate, built v1," a separate, L-numbered
  model with no concept page of its own. [verbatim] ([loop-taxonomy-graph-and-l-model-conflict-2026-08-13-26e0d2:T2])
- **The graph was deliberately built against its own flattering tendency**: "A clean
  node-and-edge diagram flatters the architecture — it makes discipline look like machinery. That's
  the coordinator-root shape: a proxy surface that reads as verification." Every node therefore
  carries a status colour and, where one exists, its live falsifier. [verbatim] ([loop-taxonomy-graph-and-l-model-conflict-2026-08-13-26e0d2:T2])
- **FBC is shown as unmeasured, not built: 125 runs, 1 sealed, 124 UNKNOWN**; EARS is shown amber
  because its own falsifier already fired on its first run; the anchor/fork-fan mechanism is shown
  as a dashed gap. [verbatim] ([loop-taxonomy-graph-and-l-model-conflict-2026-08-13-26e0d2:T2])
