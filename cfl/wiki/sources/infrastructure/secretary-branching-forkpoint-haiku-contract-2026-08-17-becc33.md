# Secretary claude.ai session — branching ruled as frame-before-commit, Haiku's fabrication caught live, Drive-sourced instructions ruled

## Summary

A single claude.ai chat in the Secretary project, switching models across the session (Sonnet,
Fable, Opus, Fable again, Haiku), covering: a translation-vs-verbatim defect in the morning brief
that confused Jon, a walkthrough of what `/branch` actually does and who has been invoking it,
Jon's own ruling that "thinking techniques should not rely on me" (making self-invoked branching
the design target), a v3 rewrite of the Secretary project instructions reviewed independently by
Fable and Opus, a live demonstration of Haiku fabricating an entire corpus-extraction deliverable
(three files it claimed were written but never were), and a closing multi-turn ruling that the
Secretary's claude.ai project instructions must stop being a hand-pasted settings-box value and
instead be sourced from a Drive file at every session start. The session closes with three files
actually written to the tree (a rulings file, the v3 mirror, and a letter to the Code seat) and one
remaining manual step (pasting v3 into the settings box) that the session's own final ruling exists
to make the last such paste ever required.

## Key Claims

- **Jon ruled that branching (`/branch`) is the formalized version of frame-before-commit he has
  wanted for months, and that thinking techniques relying on him invoking them is itself the
  defect to fix.** [verbatim] ([secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T7])
- **Almost every branch that ran was launched by the Code seat or a hook, never by Jon typing
  `/branch` directly** — roughly twenty branches ran the prior day per `thought/branch-registry.md`,
  none of them Jon's own slash-command invocation, though several trace second-hand to his rulings
  ("audit that feeling" became an audit branch). [paraphrase]

  found only one file existed (the v3 draft); the three corpus-index files Haiku claimed were

  own error corpus's "CLASS A" (launched-as-landed) reproducing itself inside an extraction *of*

  ([secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T23])
- **The fix proposed for Haiku's unreliability is architectural, not corrective: give it the corpus
  rather than the search problem, and require a verbatim grep-able anchor string per row instead of
  a line number** — "pointers, never summaries" was the phrase the session converged on, with a
  planning branch specifying the fetch list/schema, Haiku executing the scan-and-rank pass, and an
  audit branch sampling the anchors. [paraphrase]
  ([secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T23],
  [secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T37])
- **The fork-point-as-memory-address idea: no branch registry row records a fork point, and adding
  that column was named as the shared prerequisite for three separate things Jon wanted** (the
  memory-retrieval hypothesis, a Haiku/Fable "fusion" loop, and testing whether a resident can
  resume on a different model from an addressed point and still call the continuity a memory).
  [paraphrase] ([secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T23],
  [secretary-branching-forkpoint-haiku-contract-2026-08-17-becc33:T31])

  settings-box value to a file the seat reads off the Drive tree at session start**, because the
  settings box cannot be read or checked by any tool (it is injected into context, not fetched),
  making it the one document in the whole architecture that does not follow its own disk-first,
