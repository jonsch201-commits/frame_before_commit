## Key Claims

- **The session redefined Jon's test as the acceptance test, without saying so** — defensible,
  since only Jon can trigger a real compact, but the critic calls the redefinition itself silent
  and names it "the same substitution shape as the coin-flip trigger" flagged earlier that day.
  [paraphrase] ([secretary-day-one-arm-proof-inference-fork-2026-08-15-ec3d2d:T356])
- **SHOULD HAVE DONE AND DID NOT: establish provenance of `compact-capture.ps1` before installing
  trust in it.** The script materialized at 17:16:17 with no courier letter, no signature, and no
  registry row — the inbound listing around that time shows no coordinator deposit besides the
  secretary's own work order. The session reviewed WHAT the script does and test-fired it, but
  never recorded WHO wrote it; if a coordinator wrote directly into the Secretary tree, that would
  violate the delivery-only write scope the secretary itself observes toward every other trunk — a
  boundary question absorbed without being flagged. [verbatim] ([secretary-day-one-arm-proof-inference-fork-2026-08-15-ec3d2d:T356])
- **THIN INFERENCE SOLD WITH A HEDGE**: the readiness report stated "T-2 installed... your next
  message should appear automatically in `rulings/jon-arrivals-raw.md`," and promoted this to
  "arms on next prompt — Jon's next message appearing there IS the arm-proof." The only evidence
  that mid-session settings edits arm dynamically comes from Stop-event hooks (fired 16:51/16:53);
  whether UserPromptSubmit arms the same way for a mid-session edit is untested inference from a
  different event type. The critic notes that if the hook does NOT arm until relaunch, the
  post-compact session will find an empty `jon-arrivals-raw.md` and must read that as "unarmed,"
  not as "Jon said nothing" — a distinction the brief itself does not state, which the critic
  calls "the program's oldest documented defect." [verbatim] ([secretary-day-one-arm-proof-inference-fork-2026-08-15-ec3d2d:T356])
