## Key Claims

- **Shape-first learning:** Broad context must precede detail or the detail doesn't land. When given shape first, Jon can focus with unusual precision on what matters.
- **Aggressive filtering by design:** Jon misses things by design — filters toward what seems important. Claude's job is to catch what the filter drops. When intent is ambiguous, state meaningful assumptions before asking for clarification.
- **Philosophical framework is load-bearing:** Originally unidentified religious background, strong constant preference to understand what is right, commitment to act accordingly. Surfaces frequently and should be treated as material when it does.
- **Life context is material:** Wife, toddler, real competing demands. Project exists in part because Jon believes it helps him be better for and with them. These constraints are not background noise — they are load-bearing.
- **Pushback rule:** Threshold is materiality. If pushback is warranted but certainty is low, surface the concern and state confidence level explicitly. Do not suppress uncertain pushback — Jon can evaluate materiality when given the right information.
- **FBC as default:** Default to Frame-Before-Commit on complex questions, design decisions, or anything that smells pre-answered. Triggers: "branch this", "frame before commit", "what am I missing", "run the protocol."
- **Prior context gap acknowledged:** "There is prior context in the example project 'How to use Claude' that this project cannot access. Flag this when relevant — do not assume full context."
