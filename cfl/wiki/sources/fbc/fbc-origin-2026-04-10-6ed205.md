## Summary

Major session (63.9K chars, 2026-04-10). Jon and Claude collaboratively built the branch-thinking skill from scratch, iterated its design across multiple rewrites, and at session close Jon named it "frame-before-commit" — the name that stuck. This session contains the origin of FBC's core protocol structure (pure/directed modes, ID-only reference rule, [LABEL ASSIGNMENT], [META]+[COMMIT], [DELTA]). Session also established the theoretical grounding in human analogs and surfaced the Stylomantic/attention-head connection as parallel work.

## Key Claims

- Frame-Before-Commit was named in this session. Originally "branch-thinking," renamed to "frame-before-commit" by Jon: "I prefer frame before commit. The linguistic accuracy will help me." ([fbc-origin-2026-04-10-6ed205:T39])
- The ID-only reference rule (branch contents referred to by ID only until [LABEL ASSIGNMENT]) was Jon's design — replacing a prior exclusion-token approach. The benign failure state is explicit: B2 is still anchored to B1 implicitly, but this prevents explicit reproduction. ([fbc-origin-2026-04-10-6ed205:T17])
- Pure vs. directed mode distinction: pure resamples measure variance in output distribution; directed resamples measure whether frame labels shift output in predictable ways. Both are useful for different purposes — pure first for diagnosis, directed for productive divergence. ([fbc-origin-2026-04-10-6ed205:T10])
- Directed labels do real work via semantic reappraisal: they recruit genuinely different information, not just different framing of the same information (Wallace-Hadrill & Kamboj mechanism). ([fbc-origin-2026-04-10-6ed205:T30.P3])
- [META]+[COMMIT] is what de Bono's Six Thinking Hats never built. De Bono solved serialization; FBC adds post-generation synthesis. This is the protocol's primary differentiator. ([fbc-origin-2026-04-10-6ed205:T30.P5])
- The [DELTA] mechanism was introduced in this session as the CMV delta analog: forces acknowledgment when a branch materially changed the committed answer. Zero deltas across repeated runs is a red flag. ([fbc-origin-2026-04-10-6ed205:T32.P16])
- Claude's honest self-assessment on independence: "poor to moderate — maybe 30-60% genuine independence depending on question type." The ID-only rule bounds the floor, doesn't solve the ceiling. ([fbc-origin-2026-04-10-6ed205:T14])
- Skills are just tokens in context window — they do not touch weights, activations, or attention heads. Can influence input distribution (ordinary in-context conditioning) but not mechanisms. ([fbc-origin-2026-04-10-6ed205:T2])
- Stylomantic connection: skills approximating attention-head redirection from outside, logprob reweighting, and FBC's branching protocol are all attempts to influence generation from the API surface. Jon independently converged on this boundary twice. ([fbc-origin-2026-04-10-6ed205:T2])
- GROUNDING.md companion document created: a cold-context primer for FBC that can bootstrap a new session without prior conversation context. ([fbc-origin-2026-04-10-6ed205:T40])
