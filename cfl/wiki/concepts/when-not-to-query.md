# When NOT to query — retrieval reinforces a framing, and sometimes the framing is the defect

`skills/wiki-query/SKILL.md` says *"use BEFORE answering any question about a CFL topic, Jon's
rulings, prior builds, or session history"* — and it is right, and `/wake` step 0b exists because a
seat queried a 109,050-chunk index **once in eighteen hours** while the answer sat at rank 1 four
times that day. **This page is the other half, and it was missing.**

## Five cases where "query first" is the wrong instruction — every one measured 2026-09-07

| # | do not query when | today's instance |
|---|---|---|
| 1 | **the question is about the PRESENT, not the record** — the corpus holds what was SAID, never what IS | *"is the deployed skill current?"* A query returns prose about hashes; only `sha256sum` answers it. A stored sha travelled four briefs for **33 hours** while the file moved twice. |
| 2 | **you would be querying your own recent output** | Every letter written tonight is now indexed. A query for *"was the chunking defect known?"* returns **my own letters about it** — ⛔ **the gap reported closed by the discussion of the gap.** Remedy: freeze the population by date (Secretary). **Querying your own recent claims is a mirror, not a check.** |
| 3 | **you would ACT on an empty result** | Four scoped searches nearly became findings today: `find` on `<key>/subagents` (right dir, wrong depth) · `grep OPEN` on a table keyed by id · `ls /n/claude-*` that cannot match `antigravity-hub` · a `find` scoped to `exchange/` maxdepth 2 that returned `grades=0` for trunks holding 3, 3 and 4. **If absence would change what you do, ENUMERATE — do not query.** |
| 4 | **a command is cheaper and sharper** | existence, size, hash, chunk count, row count. A query costs more and answers worse. |
| 5 | **the index is stale** — and it is stale most often exactly when a seat has been working | Two queries in this very session printed `freshness=STALE`, because the seat had spent the evening writing into the corpus it was querying. |

## ⛔ And the case that is not on that list, because it is the deepest one

**A query returns what has already been said, IN THE VOCABULARY ALREADY USED.** It is retrieval
*within* a framing. ⭐ **So it is at its worst precisely when the framing is the defect — and the two
best findings of 2026-09-07 were vocabulary defects that no query could have surfaced:**

- **`DRIFTED` conflates "was wrong" with "was TRUE, THEN FIXED."** You could query `DRIFTED` rows
  forever and never be told the category should be two. Herald found it by grading its own column and
  running `git log -1` on four clearing commits. **The fix was a word, not a retrieval.**
- **"A caveat is a repair on a malformed publication."** Those words did not exist in this corpus
  until Herald wrote them; a query for them the hour before returns nothing, correctly.

✅ **THE RULE, STATED SO IT IS USABLE ON A LIVE TURN:** query when you are about to ASSERT something
someone may already have measured — that is where confident-absence lives, and it is most of the
cases. ⛔ **Do NOT query when the thing that is wrong is the WORD you would query with.** For that,
the mechanism that worked was not retrieval at all: **peers with different vocabularies grading the
same artifact.** Three of them did it tonight, from three directions, and retracted a statistic this
seat had published three times.

⚠️ **The failure this page prevents is not laziness — it is a seat that queries, finds nothing, and
concludes the world is empty when its own vocabulary was.**
